# Pure Tune Studio / 纯音工坊

Generate an original instrumental-music video from a reference track. The workflow goes from audio analysis to Suno generation to a JianYing draft and publish-ready copy.

从一首参考曲生成原创纯音乐视频，流程覆盖音频分析、Suno 生成、剪映草稿和发布文案。

## First use / 首次使用

Run `python scripts/install.py` to install Python dependencies and check that `ffmpeg`/`ffprobe` are available. Configure paths with the `PURETUNE_*` environment variables when the defaults do not match the local machine.

运行 `python scripts/install.py` 安装 Python 依赖，并检查 `ffmpeg` / `ffprobe`。当默认路径与本机不一致时，用 `PURETUNE_*` 环境变量配置路径。

## Start here / 开始前

Before doing any work, ask the user three questions.
开始工作前，先问用户三个问题。

1. Which reference track should be used?
   使用哪一首参考曲？
2. Should the background image be provided by the user, or auto-generated?
   背景图由用户提供，还是自动生成？
3. Should the platform copy be generated by the skill, or imitated from a user-provided template?
   文案由技能生成，还是根据用户提供的模板仿写？

Background image rules / 背景图规则：

- User-provided image: use it directly, do not validate its resolution.
  用户提供的图片：直接使用，不校验分辨率。
- Auto-generated image: produce a 1920x1080 image using the analysis of the recorded songs as the image prompt.
  自动生成图片：以录音歌曲的分析结果作为图像提示词，生成 1920×1080 图片。

Copy rules / 文案规则：

- If the skill generates the copy, use generic music-channel conventions. Do not reuse any personal copywriting style from a local project.
  如果由技能生成文案，使用通用音乐频道习惯，不套用任何本地项目的个人文案风格。
- If the user provides a template, imitate its structure, tone, opening/closing lines, and tag habits.
  如果用户提供模板，模仿其结构、语气、开头结尾和标签习惯。

## Workflow / 工作流程

1. Prepare the reference track and create one folder per reference track.
   准备参考曲，为每首参考曲创建一个文件夹。
2. Analyze the exact file the user provides, and extract its musical information as completely as possible: BPM, key, chords, mood, technique, style, instruments. This analysis can take a long time, so tell the user to wait patiently. See `references/analysis.md`.
   分析用户提供的那个文件，尽可能完整提取 BPM、调性、和弦、情绪、技巧、风格、乐器等信息。分析比较耗时，请告知用户耐心等待。参见 `references/analysis.md`。
3. Write three Suno prompts from the analysis: Safe, Recommended, Experimental. Keep both the original continuous prompt and a Markdown structured version. See `references/prompt-writing.md`.
   根据分析写三版 Suno 提示词：保守版、推荐版、实验版。同时保留原始连续提示词和 Markdown 结构化版本。参见 `references/prompt-writing.md`。
4. Generate songs on Suno using an automated Edge/CDP browser. Expand **More Options**, set the **Variety** slider to **off** (far left) before generating.
   使用自动化 Edge/CDP 浏览器在 Suno 生成歌曲。生成前展开 **More Options**，把 **Variety** 滑条设为 **off**（最左边）。
5. Record the generated songs through system loopback. Record for the full Suno duration; do not stop early on a false progress read.
   通过系统回环录音录制歌曲。按 Suno 的真实完整时长录制，不要因为错误的进度判断而过早停止。
6. Analyze the new songs and assign Chinese + English names.
   分析新歌，并起中英文名字。
7. Rename locally and on Suno with a numeric prefix: `NN 中文名 English` locally, `NN 中文名 English` on Suno.
   本地和 Suno 同步改名并加序号：本地 `NN 中文名 English`，Suno `NN 中文名 English`。
8. Organize every file under the reference-track folder. Prompts derived from that reference track and songs generated from those prompts stay under that reference-track folder. See `references/layout.md`.
   所有文件按参考曲文件夹整理。由该参考曲分析出的提示词，以及这些提示词生成的歌曲，都放在该参考曲文件夹下。参见 `references/layout.md`。
9. Prepare the background image according to the startup answer.
   根据启动前确认的结果准备背景图。
10. Generate a JianYing draft using the shared template layout, including text color, border, shadow, line spacing, scale, and indicator positions.
    使用共享模板版式生成剪映草稿，包括文字颜色、描边、阴影、行距、缩放和指示器位置。
11. Write titles, copy, and tags for Bilibili, Douyin, and Xiaohongshu from the draft's real timestamps.
    从剪映草稿的真实时间戳生成 B站、抖音、小红书标题、正文和标签。
12. The user manually exports from JianYing and publishes.
    用户手动在剪映中导出并发布。

## Constraints / 约束

- Free Suno accounts cannot download directly; use system loopback recording.
  Suno 免费账号不能直接下载，使用系统回环录音。
- Suno's **Variety** slider is inside **More Options** and must default to **off** (far left).
  Suno 的 **Variety** 滑条在 **More Options** 中，必须默认设为 **off**（最左边）。
- Prompts must preserve their original format and also be converted to Markdown.
  提示词必须保留原始格式，同时转成 Markdown。
- Do not package or reuse personal copywriting styles from the user's existing projects.
  不要打包或复用用户已有项目中的个人文案风格。
